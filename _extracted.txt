1. PLANTEAMIENTO DEL PROBLEMA
1.1 Contexto
La Inteligencia Artificial (IA) está transformando aceleradamente todos los sectores de la sociedad: medicina, educación, transporte, industria y entretenimiento. Sin embargo, en Colombia y en la mayoría de los países latinoamericanos, los estudiantes de educación básica y media (K-12) terminan su ciclo escolar sin ningún conocimiento sobre qué es la IA, cómo funciona, ni cómo impactará su vida profesional y cotidiana.

Esta brecha formativa no es solo un problema académico — es un problema de equidad y competitividad. Los jóvenes que no comprendan los fundamentos de la IA quedarán en desventaja en un mercado laboral que ya exige estas competencias como base.

1.2 Descripción del Problema
Las instituciones educativas K-12 carecen de una plataforma digital estructurada, accesible y adaptada pedagógicamente que permita enseñar conceptos de Inteligencia Artificial de forma interactiva. Los docentes no cuentan con herramientas para crear, asignar y evaluar actividades de IA, ni para hacer seguimiento del progreso individual de sus estudiantes. Los administradores no tienen mecanismos para gestionar el contenido educativo ni para generar reportes de desempeño académico.

1.3 Pregunta de Investigación
¿Cómo diseñar e implementar una plataforma web que permita la alfabetización en Inteligencia Artificial para estudiantes K-12, garantizando la gestión pedagógica por parte de docentes y administradores, el seguimiento del progreso individualizado y la retroalimentación inmediata al estudiante?

1.4 Justificación
• Colombia enfrenta una brecha digital significativa en competencias tecnológicas avanzadas que impacta la competitividad del país.
• Los estándares internacionales (UNESCO, OCDE) recomiendan incluir alfabetización en IA desde la educación básica.
• Los docentes necesitan herramientas concretas para enseñar IA sin requerir formación avanzada en programación.
• Una plataforma centralizada permite escalar la enseñanza de IA a múltiples instituciones con diferentes niveles educativos.
• El seguimiento del progreso permite identificar estudiantes en riesgo y adaptar la enseñanza de manera oportuna.

3. ALCANCE DEL SISTEMA
3.1 Alcance Funcional — Lo que SÍ incluye el sistema
Área
Descripción del Alcance
Gestión de usuarios
Registro, autenticación, modificación, desactivación y gestión de roles para Estudiantes K-12, Docentes y Administradores. Matrícula en instituciones educativas.
Gestión de contenidos
Creación, consulta, modificación y eliminación de módulos educativos sobre IA, organizados por nivel educativo (K-12) y tipo de contenido (Fundamentos, Ética, Programación, Robótica).
Actividades interactivas
Creación y asignación de actividades pedagógicas (cuestionarios, simulaciones, ejercicios, debates). Ejecución interactiva con retroalimentación inmediata (&lt; 1s) y guardado automático del progreso.
Seguimiento del aprendizaje
Registro automático del progreso por actividad (PROGRESO_ESTUDIANTE) e historial por módulo (HISTORIAL_PRACTICA). Consulta en tiempo real por docentes.
Reportes y exportación
Generación de reportes individuales, grupales y globales en formato PDF o Excel. Descarga desde almacenamiento en nube (S3). Máximo 5 segundos para grupos de hasta 50 estudiantes.
Seguridad
Autenticación con hash bcrypt, bloqueo automático tras 5 intentos fallidos, log de seguridad, control de acceso por rol con permisos diferenciados.
Accesibilidad y compatibilidad
Interfaz responsiva (320px–1920px), compatible con Chrome, Firefox y Edge. Cumple WCAG 2.1 nivel AA.

3.2 Alcance NO funcional — Lo que NO incluye el sistema
Exclusión
Justificación
Videollamadas o comunicación en tiempo real (chat, videoconferencia)
Fuera del alcance pedagógico definido. Existe plataformas especializadas (Zoom, Teams) para este fin.
Pagos o transacciones financieras
El sistema es de uso institucional gratuito. No requiere módulo de cobros.
Integración con Moodle, Google Classroom o plataformas LMS externas
Se diseña como sistema independiente para garantizar control total sobre los datos y la experiencia de usuario.
Generación automática de contenido con IA generativa (ChatGPT, etc.)
El contenido es creado y curado por docentes y administradores certificados para garantizar calidad pedagógica.
Aplicación móvil nativa (Android/iOS)
El diseño responsivo cubre dispositivos móviles sin necesidad de app nativa en esta versión.
Autenticación biométrica o con redes sociales
Se usa autenticación por correo y contraseña con bcrypt para máxima seguridad y simplicidad institucional.

4. OBJETIVO GENERAL
Diseñar una plataforma web de alfabetización en Inteligencia Artificial para estudiantes K-12 que permita el aprendizaje interactivo mediante módulos y actividades pedagógicas adaptadas al nivel escolar, el seguimiento individualizado del progreso académico y la gestión integral del contenido educativo por parte de docentes y administradores, aplicando las metodologías de Ingeniería de Software para garantizar calidad, trazabilidad y escalabilidad del sistema.

8.2.5 Entregable 11: Script DDL

-- DDL — Plataforma Alfabetización en IA K-12 | PostgreSQL 15 | Esquema 3FN

DROP TABLE IF EXISTS REPORTE,HISTORIAL_PRACTICA,PROGRESO_ESTUDIANTE,ACTIVIDAD,
    TIPO_ACTIVIDAD,MODULO,TIPO_CONTENIDO,MATRICULA,USUARIO,INSTITUCION,NIVEL_EDUCATIVO,ROL CASCADE;

CREATE TABLE ROL (id_rol SERIAL PRIMARY KEY, nombre_rol VARCHAR(50) NOT NULL UNIQUE
    CHECK (nombre_rol IN (&apos;Estudiante&apos;,&apos;Docente&apos;,&apos;Administrador&apos;,&apos;Coordinador&apos;,&apos;Directivo&apos;)),
    descripcion TEXT, permisos JSONB, activo BOOLEAN NOT NULL DEFAULT TRUE);

CREATE TABLE NIVEL_EDUCATIVO (id_nivel SERIAL PRIMARY KEY,
    codigo_nie VARCHAR(20) NOT NULL UNIQUE, nombre_nivel VARCHAR(100) NOT NULL,
    rango_grado VARCHAR(20) NOT NULL);

CREATE TABLE TIPO_CONTENIDO (id_tipo_contenido SERIAL PRIMARY KEY,
    nombre_tipo VARCHAR(100) NOT NULL UNIQUE, descripcion TEXT);

CREATE TABLE TIPO_ACTIVIDAD (id_tipo_actividad SERIAL PRIMARY KEY,
    nombre_tipo VARCHAR(100) NOT NULL UNIQUE, descripcion TEXT);

CREATE TABLE INSTITUCION (id_institucion SERIAL PRIMARY KEY,
    nombre VARCHAR(200) NOT NULL, municipio VARCHAR(100) NOT NULL,
    tipo VARCHAR(10) CHECK (tipo IN (&apos;publica&apos;,&apos;privada&apos;)),
    niveles_educativos TEXT, contacto VARCHAR(200));

CREATE TABLE USUARIO (id_usuario SERIAL PRIMARY KEY, nombre VARCHAR(100) NOT NULL,
    apellido VARCHAR(100) NOT NULL, correo VARCHAR(150) NOT NULL UNIQUE
    CHECK (correo ~* &apos;^[A-Z0-9._%+\-]+@[A-Z0-9.\-]+\.[A-Z]{2,}$&apos;),
    contrasena VARCHAR(255) NOT NULL,
    id_rol INT NOT NULL REFERENCES ROL(id_rol),
    id_nivel INT REFERENCES NIVEL_EDUCATIVO(id_nivel),
    fecha_registro TIMESTAMP NOT NULL DEFAULT NOW());

CREATE TABLE MATRICULA (id_matricula SERIAL PRIMARY KEY,
    id_usuario INT NOT NULL REFERENCES USUARIO(id_usuario) ON DELETE CASCADE,
    id_institucion INT NOT NULL REFERENCES INSTITUCION(id_institucion) ON DELETE CASCADE,
    fecha_matricula TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (id_usuario, id_institucion));

CREATE TABLE MODULO (id_modulo SERIAL PRIMARY KEY, titulo VARCHAR(200) NOT NULL,
    descripcion TEXT NOT NULL,
    id_tipo_contenido INT NOT NULL REFERENCES TIPO_CONTENIDO(id_tipo_contenido),
    id_nivel INT NOT NULL REFERENCES NIVEL_EDUCATIVO(id_nivel),
    area_curricular VARCHAR(100),
    id_docente INT NOT NULL REFERENCES USUARIO(id_usuario),
    activo BOOLEAN NOT NULL DEFAULT TRUE);

CREATE TABLE ACTIVIDAD (id_actividad SERIAL PRIMARY KEY, titulo VARCHAR(200) NOT NULL,
    descripcion TEXT NOT NULL,
    id_tipo_actividad INT NOT NULL REFERENCES TIPO_ACTIVIDAD(id_tipo_actividad),
    id_modulo INT NOT NULL REFERENCES MODULO(id_modulo) ON DELETE CASCADE,
    id_docente INT NOT NULL REFERENCES USUARIO(id_usuario),
    instrucciones TEXT NOT NULL, criterio_evaluacion TEXT NOT NULL,
    puntaje_maximo INT NOT NULL CHECK (puntaje_maximo &gt; 0),
    fecha_creacion TIMESTAMP NOT NULL DEFAULT NOW());

CREATE TABLE PROGRESO_ESTUDIANTE (id_progreso SERIAL PRIMARY KEY,
    id_estudiante INT NOT NULL REFERENCES USUARIO(id_usuario),
    id_actividad INT NOT NULL REFERENCES ACTIVIDAD(id_actividad),
    puntaje_obtenido NUMERIC(6,2) DEFAULT 0,
    fecha_realizacion TIMESTAMP NOT NULL DEFAULT NOW(),
    estado VARCHAR(20) NOT NULL DEFAULT &apos;en_progreso&apos;
        CHECK (estado IN (&apos;completado&apos;,&apos;en_progreso&apos;)),
    retroalimentacion JSONB,
    UNIQUE (id_estudiante, id_actividad));

CREATE TABLE HISTORIAL_PRACTICA (id_historial SERIAL PRIMARY KEY,
    id_estudiante INT NOT NULL REFERENCES USUARIO(id_usuario),
    id_modulo INT NOT NULL REFERENCES MODULO(id_modulo),
    fecha_inicio TIMESTAMP NOT NULL, fecha_fin TIMESTAMP NOT NULL,
    puntaje_total NUMERIC(8,2) NOT NULL DEFAULT 0,
    actividades_completadas INT NOT NULL DEFAULT 0,
    modulo_aprobado BOOLEAN NOT NULL DEFAULT FALSE);

CREATE TABLE REPORTE (id_reporte SERIAL PRIMARY KEY,
    tipo VARCHAR(20) NOT NULL CHECK (tipo IN (&apos;individual&apos;,&apos;grupal&apos;,&apos;global&apos;)),
    rango VARCHAR(300) NOT NULL, fecha_generacion TIMESTAMP NOT NULL DEFAULT NOW(),
    id_generado_por INT NOT NULL REFERENCES USUARIO(id_usuario),
    id_institucion INT REFERENCES INSTITUCION(id_institucion),
    formato VARCHAR(10) NOT NULL CHECK (formato IN (&apos;PDF&apos;,&apos;Excel&apos;)),
    contenido_url VARCHAR(500) NOT NULL);

-- Vista: progreso completo por estudiante
CREATE VIEW v_progreso_completo AS
SELECT u.nombre||&apos; &apos;||u.apellido AS estudiante, m.titulo AS modulo,
    a.titulo AS actividad, pe.estado, pe.puntaje_obtenido, a.puntaje_maximo,
    ROUND((pe.puntaje_obtenido/a.puntaje_maximo)*100,1) AS porcentaje
FROM PROGRESO_ESTUDIANTE pe
JOIN USUARIO u ON pe.id_estudiante=u.id_usuario
JOIN ACTIVIDAD a ON pe.id_actividad=a.id_actividad
JOIN MODULO m ON a.id_modulo=m.id_modulo
ORDER BY u.id_usuario, m.id_modulo, a.id_actividad;
